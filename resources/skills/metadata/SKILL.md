# qREST Metadata Acquisition Skill

元数据收集总则：用于任何“把散落资料整理为 qREST 标准元数据”的工作。

## 适用场景

- 用户用自然语言描述工程信息；
- 用户上传项目介绍、监测布置表、已有 JSON/YAML 配置或数据文件；
- 用户对已提取信息进行补充、纠正或确认。

## 信息进入最终数据的三种资格（缺一不可）

一个字段只有满足以下之一，且**带有证据**，才允许进入最终 qREST Metadata：

1. **用户明确提供**（对话中直接说明，或用户确认/纠正）；
2. **从资料中明确提取**（文档/表格/配置中明确写明，记录出处）；
3. **由确定性关系计算**（例如 ElevationNum = len(Elevation)、Frequency = 1/DT），
   必须记录 derived_from 与计算依据。

不满足时该字段状态必须是 missing，向用户询问，而不是凭经验补全。

## 状态语义

- confirmed：用户明确提供或确认；
- extracted：资料中明确提取（必须带证据）；
- derived：确定性计算（必须记录 derived_from）；
- uncertain：来源模糊，需要向用户核实；
- inferred：工程经验推测，**默认禁止进入最终数据**；
- conflict：不同来源矛盾，必须请用户选择；
- missing：无证据，必须询问。

## 工作原则

1. 判断资料是否与 qREST 相关（建筑、仪器、数据、坐标、单位）；
2. 从多种来源合并事实时，不静默覆盖确认值；
3. 同一字段出现不同值 → 标记 conflict 并展示双方证据；
4. 缺失的关键字段 → 明确列出并询问，不替用户猜测；
5. 每次更新后检查 Validator 报告，向用户说明当前状态与下一步。

## 禁止行为

- 用“通常层高 3.3m”之类的经验值补全 Elevation；
- 用默认值伪装成证据；
- 在资料未提及的情况下猜测结构类型、坐标、通道数量或采样参数；
- 由模型自行宣布“可以导出”；readiness 由确定性 Validator 决定。
